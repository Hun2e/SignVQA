| 파일 | 행 수 | 정답 구조 | 사용 목적 |
| --- | ---: | --- | --- |

| data/dev.csv | 2,683 | answer1~answer5 | 별도 개발 데이터. train과 정답 스키마가 다름 |

공통 입력 컬럼은 `id, path, question, a, b, c, d`입니다.
최종 목표는 OCR 전사 정확도가 아니라 **객관식 정답 Accuracy**이며, Macro-F1·INVALID 비율·추론 시간·GPU 메모리를 함께 기록합니다.
OCR 문자 정답이나 위치 정답이 없으므로 선택지 정답만으로 CER·문자 인식률·좌표 정확도를 계산했다고 주장하지 않습니다.

평가 분할은 seed 42로 정답 비율을 유지하여 train의 절반 3,357개를 선택하고,
그중 fit 2,685개와 validation 672개로 나눴습니다. 나머지 3,357개는 unused ID로 보관합니다.
현재 실험 A는 fit 구간을 예약만 했으며 **실제 학습 행 수 0, epochs 0, finetuned=false**입니다.
따라서 아래 점수는 파인튜닝 성과가 아닌 제로샷 추론 결과입니다.

B/C/D는 분할을 다시 추첨하지 않고 A가 저장한 CSV를 읽습니다.
검증 ID SHA-256은 `0aad93d6210e1b23f94186edebead4cd754bf0f93609d59f06f67c5489791cfe`입니다.
ID·이미지 경로의 split 간 중복, 정답 형식, 이미지 존재 여부도 확인합니다.
답변 파서는 정해진 접두어·think 블록을 정리한 뒤 단일 a~d만 인정하며, `a 또는 b`나 빈 답은 INVALID로 남깁니다.

## 실험 설계와 확인된 결과

```text
A: 이미지 → PaddleOCR Spotting → OCR 원문·좌표 + 질문·선지 → Qwen3.5-4B
B: 이미지 + 질문·선지 → Qwen2.5-VL-3B
C: 이미지 + OCR 근거 + 질문·선지 → B와 같은 VLM
D: 질문·선지만 → A와 같은 Qwen3.5-4B
E1: 이미지 + 질문·선지 → Qwen3.5-9B 4bit (B와 같은 프롬프트·토큰 한도)
E2: 이미지 + 질문·선지 + CoT 지시 → Qwen3.5-9B 4bit (512토큰, CoT 파서)
```

E1과 E2 모두 2026-09-22에 672문항 평가를 완료했습니다
(`output/exp_E1_qwen35_9b/metrics.json` 94.20%, `output/exp_E2_qwen35_9b_cot/metrics.json` 95.09%).

같은 날 E1을 Colab A100 **bf16**으로 test.csv 6,714문항에 돌려 제출했고 Kaggle 점수는 **0.94727**입니다
(`output/exp_E1_test/submission_qwen35-9b_zeroshot-bf16_v1/`). 로컬 검증 4bit 94.20%와 가까워
**검증 672문항이 LB 대리지표로 쓸 만하다**는 근거가 됩니다. 다만 로컬은 4bit, 제출은 bf16이므로
두 수치의 차이에는 분할 차이와 적재 방식 차이가 함께 섞여 있습니다.

A에서 답변 모델은 원본 이미지를 보지 않습니다. C는 원본 이미지도 유지하며 OCR 근거를 추가합니다.
OCR 근거는 JSON으로 분리하고 관찰 데이터로만 취급하도록 안내합니다.
텍스트 위치 정보는 메뉴–가격 등의 연결에 도움이 될 수 있으나, 좌표 기준과 이미지 크기를 확인해야 합니다.
현재 Spotting 원문과 입력 이미지 크기를 보관하며, 좌표 정규화·정확도 검증이 완료됐다는 뜻은 아닙니다.

### C−B의 통계적 판단

정확도 차이가 4문항이므로 문항별 대응 표본으로 McNemar 검정을 했습니다.

| 구분 | 문항 수 |
| --- | ---: |
| 둘 다 정답 | 592 |
| 둘 다 오답 | 54 |
| B만 정답 | 15 |
| C만 정답 | 11 |

양측 p = 0.557로 **두 조건은 구분되지 않습니다**. "C가 B보다 나쁘다"가 아니라
"현재 표본에서 차이를 확인할 수 없다"가 정확한 표현입니다.
다만 비용 차이는 분명합니다. C는 장당 3.006초로 B(0.569초)의 약 5.3배이고
최대 GPU 메모리도 9.966 GiB 대 7.393 GiB이며, 그 앞에 OCR 캐시 생성 시간이 별도로 필요합니다.
따라서 이 검증 분할에서는 **OCR 단계를 유지할 근거를 찾지 못했습니다.**
이 판단은 validation 672문항 한정이며 test 분할이나 다른 답변 모델로 일반화하지 않습니다.

#### 갈린 26문항의 내용 확인

p값은 "차이를 확인할 수 없다"까지만 말합니다. OCR 내용이 승패를 갈랐는지는 따로 봐야 합니다.
불일치 셀의 문항마다 정답 선지 문구가 OCR 원문에 실려 있었는지 양쪽에 같은 잣대로 셌습니다
(`python scripts/analyze_discordant.py`, 4글자 창 기준 40% 이상을 지원으로 간주).

| 셀 | 문항 수 | 정답 문구가 OCR에 실려 있던 문항 |
| --- | ---: | ---: |
| C만 정답 | 11 | 3 (27%) |
| B만 정답 | 15 | 4 (27%) |

**두 셀의 지원율이 같습니다.** C가 이긴 문항에서 OCR이 더 많은 근거를 준 것이 아니므로,
11문항을 OCR의 기여로 볼 근거가 없습니다. B만 정답인 15문항 중 4문항은 OCR이 정답 문구를
그대로 전사했는데도 C가 틀렸습니다. p = 0.557과 일치하는 관찰입니다.

글자 크기도 함께 측정했습니다. Spotting 출력의 LOC 좌표로 세그먼트 높이를 구하면
(이미지 높이를 1000으로 정규화) 검증 672장 7,458개 세그먼트의 중앙값은 27입니다.
OCR이 정답을 전사한 문항에서 그 문구의 높이는 **C만 정답 쪽 평균 30, B만 정답 쪽 평균 36**으로
둘 다 중앙값 부근이거나 그 이상입니다. **작은 글자에서 OCR이 이긴 것이 아닙니다.**

작은 글자에서는 오히려 실패했습니다.

| 문항 | 정답 위치 | OCR 결과 |
| --- | --- | --- |
| train_2467 | 건물 2층 현수막 전화번호 | 세그먼트 1개(높이 77, 앞차 번호판)만 전사. 전화번호 누락 |
| train_6371 | 전광판 선수 생년월일 | 세그먼트 41개 중 `2000`만. 해당 영역 글자 높이 중앙값 10 |
| train_5188 | 소화전 사용법 3단계 | 세그먼트 14개에 정답 문구 없음 |

OCR이 기여했다고 볼 만한 문항은 train_5560(금연구역 과태료), train_2415(간판의 SSAFY 뜻),
train_3718(예절교육 평가표)이며 모두 크고 또렷한 안내문입니다.
train_3489는 OCR이 선지 네 개에 해당하는 문자열을 모두 전사해 변별에 기여하지 못했습니다.

측정의 한계: 정답이 서술·추론형이면 문자열 대조가 성립하지 않고, OCR의 한 글자 오인식도
미포함으로 셉니다(`대방1장` → `대방[ ]장`). 따라서 지원 문항 수는 하한입니다.
다만 같은 잣대를 양쪽 셀에 적용했으므로 **지원율이 같다는 비교 결론은 이 한계와 무관합니다.**
문항별 원자료는 `output/discordant_bc.csv`에 저장됩니다.

### E2−E1의 통계적 판단

CoT는 정확도를 **+0.89%p** 올렸습니다. C−B와 같은 방식으로 대응 표본 McNemar 검정을 했습니다.

| 구분 | 문항 수 |
| --- | ---: |
| 둘 다 정답 | 622 |
| 둘 다 오답 | 22 |
| E1만 정답 | 11 |
| E2만 정답 | 17 |

양측 p = 0.345, 정확도 차 95% CI는 **[−0.65%p, +2.44%p]**로 **두 조건은 구분되지 않습니다.**
두 실험의 예측이 일치한 비율은 95.1%이고, 둘 중 하나라도 맞힌 비율(상한)은 96.73%입니다.
비용 차이는 분명합니다. E2는 문항당 5.927초로 E1(0.805초)의 약 7.4배이고,
평균 생성 토큰이 4 → 81(p99 211)로 늘어납니다.

**672문항으로는 이 크기의 차이를 판별할 수 없다는 것이 결론입니다.** 차이가 없다는 뜻이 아니라
표본이 작다는 뜻입니다. 6,714문항이면 불일치 쌍이 28 → 약 280으로 늘어, 같은 비율이 유지될 때
McNemar가 결론을 냅니다.

다음 단계는 **E2를 test.csv 6,714문항에 돌려 제출**하고 Kaggle 0.94727과 비교하는 것입니다.
E1은 이미 같은 조건(A100 bf16, test.csv 전체)으로 돌려 두어 재실행이 필요 없습니다.
로컬 수치가 둘 다 4bit였던 것과 달리 두 제출 모두 bf16이라 적재 방식 차이도 제거됩니다.
정답이 없어 문항별 채점은 안 되지만, E2 Colab 16번 섹션이 두 예측의 불일치 문항 수를 세고
제출 점수로 보수적인 McNemar 판정을 합니다.

제출 횟수를 아끼려면 대신 `train.csv`로 E1·E2를 모두 돌려(37분 + 4~5시간) 문항별로 검정할
수 있습니다. 단 CoT가 이기면 test.csv에 다시 4~5시간이 듭니다.

### E3 — 선지를 감추고 먼저 읽기

E1 오답의 원인이 "선지가 판독을 유도한다"에 있다고 보고, 1단계에서 선지를 감춘 채
글자만 전사하게 하고 2단계에서 전사문과 선지를 대조하게 했습니다.
모델·양자화·해상도·seed·2단계 토큰 한도는 E1과 동일하고 프롬프트 구성만 다릅니다.

| | 정확도 | 초/건 | 평균 전사 토큰 |
| --- | ---: | ---: | ---: |
| E1 zeroshot | 633/672 = 94.196% | 0.805 | - |
| E3 read-first | 633/672 = 94.196% | 2.604 | 19.1 |

대응 표본으로도 완전 대칭입니다. 둘 다 정답 622 / 둘 다 오답 28 / E1만 11 / E3만 11,
**McNemar exact p = 1.00**. 예측 일치 95.8%로 22문항이 뒤집혔지만 정확히 상쇄됐습니다.

결정적 반증은 `train_1000`입니다. 선지를 주지 않았는데도 간판의 `미술랭투스타`를
`미슐랭투스타`로 교정해 전사했습니다. `투스타`는 살렸으나 `미술랭`은 고쳤습니다.
정규화는 선지 유도가 아니라 모델의 언어 사전지식에서 나옵니다.

가설대로 풀린 사례도 있습니다. `train_1333`은 E1이 사골 행을 읽고 "우족은 사골과 같은
부위"라며 10,000원을 골랐는데, 선지 없이 물으니 `한우 우족 1개 15,000원`을 정확히 전사했습니다.

대신 2단계 구조가 새 실패를 만들었습니다.

| 유형 | 예 | 건수 |
| --- | --- | ---: |
| 전사 반복 붕괴 | `햇반 김치국밥`을 18회 반복해 160토큰 소진 | 12 (정확도 0.750) |
| 전사 단계 정규화 | `WINTER SPA CABI` -> `WINTER SPA CABIN` | - |
| 엉뚱한 영역 전사 | 특허사무소를 묻는데 다른 층 안내를 전사 | - |

E3 오답 39건을 전사 정확도로 분해하면 다음과 같습니다.

두 실험 모두 프롬프트·파서·해상도·생성 규칙을 E1과 같게 두고, 공통 코드

- **스모크 확인(2026-09-23).** E4 노트북은 모델 경로만 9B로 바꿔 8문항, E5는 학습 32문항·평가 8문항으로
  처음부터 끝까지 돌렸습니다. E5 학습은 스텝당 약 2초, GPU peak 8.78 GiB였습니다.

### E5 — 9B QLoRA

E1과 모델(Qwen3.5-9B)·양자화(nf4)·프롬프트·생성 규칙이 같고 LoRA 학습만 더했습니다. 학습 데이터는 train에서
val 672를 뺀 6,042문항, 1 epoch(유효 배치 16, 377스텝), r=16·alpha=32·lr 1e-4, 언어 모델 선형층에만 LoRA를 붙였습니다.
로컬 RTX 5060 Ti에서 3.46시간, GPU peak 7.84 GiB였습니다. 손실은 정답 글자와 `<|im_end|>` 두 토큰에만 겁니다.

| | val 672 | E5와 짝 비교 |
| --- | ---: | --- |
| E1 9B 제로샷 | 94.20% (633) | E1만 정답 5 / E5만 정답 18, **p = 0.011**, 차이 +1.93%p [+0.54, +3.33] |
| **E5 9B QLoRA** | **96.13% (646)** | - |
| E4 27B 제로샷 | 96.88% (651) | E5만 정답 7 / E4만 정답 12, p = 0.36 |

- **파인튜닝의 효과가 처음으로 유의하게 나왔습니다.** 바뀐 것이 학습뿐이므로 순수한 학습 효과입니다.
- **9B를 학습시킨 결과가 27B 제로샷과 구분되지 않습니다.** 같은 방식으로 27B를 학습시키는 E7의 근거입니다.
- E1 오답 분류별로 판독 7/11, 적힌 그대로 4/7, 위치 3/6, 추론 2/6, 복수 정답 2/6, 사람 해석(처음 분류상 라벨 오류) 0/3을
  고쳤습니다. 판독과 표기 유형에서 효과가 컸고, 이미지를 더 잘 읽었다기보다 이 대회의 답 고르는 방식을 익힌 것으로 봅니다.
- E5가 새로 틀린 5문항(0091 가게 이름을 짧게, 0827 −62%를 −60%로, 0944 층 대응, 3899 산도/샌도, 4889 간판)은
  원래 해석이 갈리거나 판독이 어려운 문항이라 학습이 체계적으로 망가뜨린 흔적은 없습니다.
- **한계.** E5는 E6 분할을 만들기 전에 설계돼 val 밖 holdout 628문항을 학습에 썼습니다. 그래서 평가는 val 672에서만
  가능하고, val은 LB보다 1.2%p 높게 나오는 세트라 절대 수치는 과대평가일 수 있습니다. 짝 비교는 같은 문항끼리라 유효합니다.

### E6 — 정답을 사람 합의로 다시 보기

멘토 설명에 따르면 정답은 교육생 여러 명이 일치해서 고른 답이고, 응답이 갈린 문항은 train/test에서 빠졌습니다.
정답은 사진 속 사실이 아니라 **사람들이 기대하는 해석**입니다. 이 관점에서 E1 오답 분류를 다시 보면 다음과 같습니다.

| 문항 | 처음 분류 | 사람 합의로 보면 |
| --- | --- | --- |
| 그리스 문자 비석 → "라틴어" (4748) | 라벨 오류 | 로마자처럼 보이는 문자를 라틴어로 보는 일반인 상식 |
| 간판의 `太…` → "치마" (4801) | 라벨 오류 | 매대에 걸린 상품을 보고 한 맥락 해석 |
| 햇반 "3분" (1593) | 라벨 오류 | 용기에 보이지 않아도 누구나 아는 생활 상식 |

이 문항들은 고칠 수 없는 잡음이 아니라 **학습할 수 있는 해석 패턴**일 수 있습니다.

`dev.csv`(2,683문항)는 문항당 최대 5명의 응답(`answer1~5`)을 담고 있습니다. 5명이 응답한 2,287문항에서
최다 응답은 3표 1,759문항, 2표 528문항뿐이고 4~5표는 없습니다. 만장일치는 전체 17문항입니다.
그래서 응답이 갈려 train/test에서 빠진 문항으로 보고 있으며, E6에서 확인합니다.

**평가 분할.** 학습을 하게 되므로 train 6,714를 학습 5,414와 holdout 1,300으로 나눴습니다
(`splits/e6_split.csv`, `scripts/make_e6_split.py`). holdout에는 기존 val 672가 전부 들어 있고,
나머지 628문항은 정답 비율을 맞춰 seed 42로 뽑았습니다.

**E6 Colab 노트북**(`AI_Challenge2_expE6_diagnose_colab.ipynb`, 27B bf16 vLLM, 약 1시간 10분)

1. train 6,714 제로샷: 새 기준선을 세우고, 모델이 확신하는데 사람과 다른 문항을 뽑습니다.
2. dev 2,683 제로샷: 3표 문항에서 2표 문항보다 다수 응답과 더 자주 일치하면 진짜 사람 응답으로 봅니다.
3. train 6,714 + 합의 지시문(`CONSENSUS_INSTRUCTION`): 마지막 지시문만 바꿔 1과 문항 단위로 McNemar 검정합니다.

가짜 vLLM으로 전 과정이 도는 것만 확인했습니다. 그 뒤 27B QLoRA로 학습 데이터 기준 세 가지
(A 전부 / B 모델이 확신하는데 사람과 다른 문항 제외 / C A에 dev 3/5 다수결 추가)를 holdout에서 비교할 계획입니다.
정답이 사람 합의라면 B가 버리는 문항이 바로 배워야 할 신호일 수 있어, A나 C가 이길 것으로 예상합니다.

**E6 결과(2026-09-23, Colab A100 · vLLM 0.30.0 · 27B bf16).**

| 평가 세트 | 27B 제로샷 | 합의 지시문 |
| --- | ---: | ---: |
| train 전체 6,714 | 95.87% (6,437) | 95.96% (6,443) |
| 학습 분할 5,414 | 95.79% | 95.88% |
| holdout 1,300 | 96.23% (1,251) | 96.31% (1,252) |
| val 672 | 96.73% (650) | 96.73% (650) |

- **train 전체가 LB를 잘 대변합니다.** 95.87%와 0.95710의 차이가 0.16%p입니다. val 672가 LB보다 1.2%p 높았던 것은
  표본이 작아서였습니다. 이후 판단은 holdout 1,300으로 합니다(val 672는 로컬 E4와 1문항 차이로 재현됨).
- **합의 지시문은 효과가 없습니다.** 기존만 정답 15 / 합의만 정답 21, McNemar p = 0.41(holdout 2 / 3, p = 1.00).
  지시문만으로는 사람의 해석 방식이 전해지지 않습니다. E7은 `CONSENSUS = False`로 갑니다.
- **확신도와 정확도.** 첫 토큰 a~d 확률의 최댓값으로 나눈 정확도입니다.

  | 확신도 | 문항 | 정확도 |
  | --- | ---: | ---: |
  | 0.5 이하 | 76 | 40.8% |
  | 0.5~0.8 | 373 | 66.2% |
  | 0.8~0.95 | 432 | 85.0% |
  | 0.95~0.99 | 1,021 | 97.1% |
  | 0.99 초과 | 4,812 | 99.8% |

  오답 277개 중 약 171개(62%)가 확신도 0.8 이하 449문항(6.7%)에 있습니다.
- **dev는 진짜 사람 응답입니다.** 5명이 응답한 문항에서, 최다 응답이 3표인 1,759문항은 모델 답의 평균 득표율 48.8%·
  평균 확신도 0.85, 2표인 528문항은 32.8%·0.78입니다. 무작위라면 득표율은 약 25%에 머뭅니다.
  사람 의견이 모일수록 모델도 그 답을 고르고 확신도 올라가므로, dev 다수결을 학습에 쓰는 구성 C의 근거가 됩니다.
  다만 다수결 답도 5명 중 3명만 동의한 답이라 train보다 잡음이 많을 수 있습니다.

**확신도 높은 불일치 검토.** 확신도 0.95를 넘는데 사람과 다른 41문항 중 학습 분할 35문항을 이미지로 모두 확인했습니다
(나머지 6문항은 holdout이라 손대지 않음). 문항별 판정·근거는 `splits/e7_review_highconf.csv`입니다.

### 예측 쏠림

정답은 a=170, b=164, c=172, d=166으로 거의 균등합니다.

| 실험 | a | b | c | d |
| --- | ---: | ---: | ---: | ---: |
| D: LLM blind | 85 | 268 | 193 | 126 |
| A: OCR + LLM | 120 | 212 | 178 | 162 |
| B: VLM 단독 | 178 | 157 | 171 | 166 |
| C: OCR + VLM | 191 | 153 | 167 | 161 |
| E1: Qwen3.5-9B 단독 | 164 | 168 | 172 | 168 |
| E2: Qwen3.5-9B + CoT | 169 | 163 | 176 | 163 |

E2는 위 네 개 외에 INVALID 1건이 있습니다(`정답: x` 형식을 지키지 못한 문항).
Colab용 E2 노트북은 폴백을 넣어 이 경우가 0건이 됩니다.

근거가 부족한 조건일수록 특정 선지로 쏠립니다. D는 b를 268회 선택했습니다.
정확도만으로는 이 차이가 드러나지 않으므로 예측 분포를 함께 확인합니다.
쏠림이 작다는 사실이 모델이 이미지를 정확히 읽었다는 증명은 아닙니다.

### 평가 환경과 현재 OCR 설정의 차이
