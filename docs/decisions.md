### 왜 OCR 단계를 접고 VLM 단독으로 갔는가

A(OCR→LLM) 68.90%, C(OCR+VLM) 89.73%, B(VLM 단독) 90.33%입니다.
OCR 근거를 **추가해도** VLM 단독보다 나아지지 않았고(C−B는 McNemar p=0.557로 판별 불가),
비용은 장당 5.3배에 OCR 캐시 생성 시간이 따로 듭니다.
그래서 이후 노선을 OCR 없이 **답변 모델을 키우는 쪽**(B → E1)으로 잡았습니다.
OCR 코드와 캐시는 버리지 않고 남겨 두었습니다. 이 판단은 val 672문항 한정입니다.

2026-09-23에 갈린 26문항의 내용을 직접 확인해 이 판단을 보강했습니다
(`scripts/analyze_discordant.py`). 정답 문구가 OCR 원문에 실려 있던 비율이
C만 정답 3/11(27%), B만 정답 4/15(27%)로 **같습니다.** 즉 C가 이긴 문항에서
OCR이 더 많은 근거를 준 것이 아니므로, 그 11문항을 OCR의 기여로 볼 근거가 없습니다.
글자 크기도 반대였습니다. OCR이 정답을 전사한 문구의 높이는 평균 30(전체 중앙값 27)으로
작은 글자가 아니었고, 정작 작은 글자에서는 실패했습니다
(train_2467은 앞차 번호판 한 줄만 전사하고 건물 현수막의 전화번호를 누락).
**OCR과 VLM의 실패 지점이 겹쳐 상보적인 구간이 생기지 않는다**는 것이 이 노선을 접은 실질적 이유입니다.

### 왜 train.csv로 더 재지 않고 test.csv 제출로 비교하는가

E2(CoT)가 E1보다 나은지는 672문항으로 판별되지 않았습니다(p=0.34).
표본을 키우는 방법은 두 가지인데, **정답이 있는 train.csv 6,714문항으로 다시 재거나**,
**test.csv에 돌려 제출하고 Kaggle 점수로 비교**하는 것입니다.

이 프로젝트는 **학습을 하지 않습니다**(실제 학습 행 수 0, epochs 0, finetuned=false).
그래서 train.csv는 "학습에 쓴 데이터"가 아니라 정답이 붙은 문제지일 뿐이고,
용도는 *제출을 쓰지 않고 미리 재보는 것* 하나뿐입니다. 꼭 거쳐야 할 단계가 아닙니다.

비용을 비교하면 test 경로가 모든 경우에 쌉니다. E1은 이미 같은 A100 bf16으로
test 전체를 돌려 뒀으므로(0.94727) E1 재실행이 필요 없고, CoT가 이기면 그 제출을 그대로 내면 됩니다.
train 경로는 E1을 37분 더 돌려야 하고, 이겨도 test에 4~5시간을 또 써야 합니다.

대신 test 경로는 문항별 정답을 모르므로 McNemar를 그대로 쓸 수 없습니다.
그래서 E2 Colab 16번 섹션에 **보수적 판정**을 넣었습니다. 점수 차이가 `c − b`를 주고
두 예측의 불일치 문항 수가 `b + c`의 상한이므로, 불일치 전부가 정오를 가른다고 놓으면
가장 불리한 p값이 나옵니다. 그 값으로도 유의하면 믿을 수 있습니다.
제출 횟수가 빠듯해지면 `SUBMISSION_CSV`를 `train.csv`로 바꿔 원래 경로로 돌아갈 수 있습니다.

## 검증한 범위와 남은 작업

- 기존 체크포인트·배치 처리 단위 테스트 9개 통과.
- Python 문법, 노트북 13개 JSON, 하위 폴더에서 경로 탐색·공통 코드 import, 외부 작업 폴더에서 run_nb 호출 확인.
- A/B/D는 저장된 672문항 지표로 완료 확인. 문서 작성 중 GPU 추론을 새로 실행하지 않음.
- C 완료(2026-09-22). C−B는 McNemar 양측 p=0.557로 차이를 확인하지 못함.
- 갈린 26문항 내용 확인(2026-09-23). 정답 문구의 OCR 전사 비율이 양쪽 셀 모두 27%로 같아,
  C만 정답인 11문항을 OCR의 기여로 볼 근거가 없음. 원자료 `output/discordant_bc.csv`.
- E1 완료(2026-09-22). 672문항 94.20%로 B(90.33%) 대비 +3.87%p. 모델 크기와 양자화 차이가 섞여 있음.
- E1의 94.20%는 표본 부족이 아님(95% CI ±1.78pp). 다만 검증 분할은 train 홀드아웃이라
  test 성능을 보장하지 않음. 같은 672문항에서 구성만 바꿔 48.36%~94.20%로 갈리므로,
  다른 파이프라인의 점수와 비교할 때는 대상 CSV·모델·파서를 먼저 맞춰야 함.
- E2 완료(2026-09-22). 672문항 95.09%로 E1 대비 +0.89%p이나 McNemar p=0.34로 판별 불가.
  비용은 문항당 7.4배. 표본이 작아 구분되지 않은 것이며 차이가 없다는 뜻이 아님.
- E1 제출 완료(2026-09-22). Colab A100 bf16, test 6,714문항 37분, **Kaggle Public 0.94727**.
